# Picker — пустой пункт в раскрытом списке

**Текущий статус: не решено в официальной Alpha UI 0.4.11; ожидается официальный выпуск.** Использовать только as-is. Патчи и локальные версии отозваны. Дальнейшие требования передаются исключительно через ui-unspec.

## Задача

Alpha UI **0.4.11**: `AppShell.context.placeholder = ''` убирает текст «Не выбрано», но `Picker` передаёт пустой placeholder в `Select`, который добавляет отдельный disabled `<option value="">`. При выбранном `nas` раскрытый список содержит лишнюю пустую строку.

## Требуемое поведение

При существующем выбранном значении и явно пустом placeholder раскрытый пикер содержит только переданные варианты. Скрытая доступная подпись, выбор, клавиатура и фокус сохраняются. Неизвестное значение не подменяется первым вариантом.

## Публичный API

Уточнить контракт существующего `Picker.placeholder?: string`: `placeholder=""` не добавляет placeholder-пункт, когда `value` соответствует одному из `options`. Для пустого/неизвестного значения сохранить disabled пустое состояние, чтобы нативный select не выбирал первый вариант молча. Контракт одинаков для React/Qwik и `HeadBar`/`AppShell.context`.

## Проверка

- При `value="local"`, единственном варианте `nas` и `placeholder=""` существует ровно один option и одна строка overlay.
- Нет пустого пространства над/под `nas` на 320 и 1680 px.
- Несколько вариантов, длинные названия, Enter/Space, стрелки, Escape, возврат фокуса и disabled работают.
- Неизвестное значение и пустой список не становятся выбранным первым вариантом.
- В приложении нет CSS-переопределений и вмешательства во внутреннюю разметку Alpha UI.
