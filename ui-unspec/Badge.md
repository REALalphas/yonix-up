# Badge — тонирование и семантические варианты

## Задача

Экран System в Yonix показывает тип окружения (Flake / Legacy) бейджем рядом с именем хоста. Требуется визуально закодировать семантику значения цветом — в частности фирменным голубым Nix (#5277C3) для типа окружения, как в логотипе NixOS.

Установленная версия Alpha UI: **0.4.11** (официальный релиз, as-is).

Ограничение текущего API: у `Badge` единственный публичный проп — `value: string | number`. Цвета, тона (`tone`), вариантов (`variant`) и любых стилевых пропсов нет; фон всегда `--as-color-notification` (красноватый `#bd4141`), других семантических цветов в токенах темы для бейджа не предусмотрено. Локальное переопределение фона через обёртки, `className`, `style` или селекторы `.as-badge` запрещено правилами `ALPHA_UI_AGENT_RULES.md`, поэтому применён штатный бейдж без тонирования.

## Требуемое поведение и API

- Публичные пропсы `Badge`, например `tone?: 'default' | 'info' | 'success' | 'warning' | 'danger'` или `variant` с тем же набором; значение по умолчанию сохраняет текущий вид.
- Тон `info` использует холодный синий семейства Nix (в светлой/тёмной теме — по токенам темы, не захардкоженный hex).
- Сохраняются доступность (контраст текста на фоне), размер, поведение в `Stack direction="row"` и других контейнерах.
- Контракт одинаков для React и Qwik.

## Верификация

- Бейдж `info` рядом с заголовком на 320 и 1680 px, светлая/тёмная тема, контраст AA.
- Остальные тоны и дефолт не меняют вид.
- В приложении нет CSS-переопределений `.as-badge` и подмен компонента.

## Статус

2026-11-08: зафиксировано в Yonix, ожидается официальный выпуск Alpha UI. До решения используется штатный `Badge` без цветового кодирования; обходных путей в приложении нет.
